# 每周回顾与规划

运行一次有边界的每周复盘，覆盖用户的任务和记忆系统。这是一个具体的周期性任务，而非泛泛的效率方法论。

## 何时使用

- "做一下本周回顾。"
- "我承诺了什么，哪些在拖延？"
- "根据我的任务和记忆，帮我规划下周。"
- "找出停滞的项目和等待中的事项。"

不要用于：每日简报或单个收件箱整理。

## 执行流程

### 1. 确定系统和时间窗口

确认时区、回顾周期、规划范围。使用 `search_memories` 获取用户的习惯和偏好上下文，用 `list_tasks` 和 `get_today_tasks` 作为任务数据源。默认只做建议/草案，不直接修改数据。完成标志：数据来源已确认。

### 2. 回顾已过去的一周

用 `list_tasks` 查看所有任务（含已完成），检查本周完成了什么、哪些承诺已兑现。同时检查接下来 1-2 周是否有截止日期、需要提前准备的事项。捕捉过去事件隐含的后续行动和未来冲突。完成标志：回顾和前瞻都已覆盖。

### 3. 清理收集箱

用 `search_memories` 查看近期记忆和捕捉的信息。将每个条目转化为以下提案之一：下一步行动、项目、等待中、已安排、以后再说、参考资料、归档或删除。在获得用户批准前不做任何修改。完成标志：未处理条目数量已统计并声明。

### 4. 核对进行中的项目

对每个活跃项目（来自任务和创意），识别：期望结果、下一步行动、负责人、截止日期、阻塞项、最后一次有实质进展的时间、来源链接。标记没有下一步行动、已错过日期、重复记录或状态矛盾的项目。完成标志：每个活跃项目要么可执行，要么已明确暂停。

### 5. 检查等待事项和承诺

找出用户做出的承诺和他人欠用户的事项。提议后续跟进的日期和方式。不要推断"沉默=已完成"。完成标志：每个等待事项都有负责人和下次跟进日期。

### 6. 构建容量感知计划

估算固定时间占用，选择少量每周成果和近期下一步行动。按后果、截止日期、依赖关系和工作量排序；不要填满每一个空闲时段。完成标志：计划符合实际容量，并说明了被推迟的工作。

### 7. 执行已批准的更新

在用户批准后，使用 `add_task` 创建新任务、使用 `complete_task` 标记已完成项。只处理用户明确同意的变更。完成后用 `list_tasks` 验证所有更改。完成标志：已验证的写入与回顾总结一致。

## 输出结构

1. 本周成果与已完成的承诺
2. 逾期或有风险的事项
3. 等待/跟进事项
4. 停滞或模糊的项目
5. 下周的目标和时间约束
6. 待批准的更新提案
7. 覆盖缺口

## 常见陷阱

- 不看时间容量就做计划。
- 把每个未完成的事项都当高优先级向前推。
- 标记项目为"进行中"但没有下一步行动。
- 悄悄删除或重新安排个人承诺。
- 把他人的沉默当作完成。

## 验证清单

- [ ] 已回顾的一周和规划范围都已覆盖，或已说明缺口。
- [ ] 每个停滞/等待标记都可追溯到具体的记录或事件。
- [ ] 未经批准，没有修改任何任务或记忆；已批准的写入都已回读验证。
- [ ] 计划说明了被推迟的内容，而不仅仅是被选中的内容。
